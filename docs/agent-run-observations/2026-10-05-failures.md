# BTC and ETH run failures on 5 October 2026

Checked `ubuntu-server` around 05:10 IST using Docker logs, PostgreSQL job records, backend health, and OpenRouter's authenticated key metadata endpoint. All times below are IST.

## Cause

Both assets use the same OpenRouter key. Model calls returned HTTP 403 with `Key limit exceeded (total limit)`. Key metadata showed a USD 20 limit, USD 20.009618912 usage, zero remaining allowance, and no configured reset. No key values or credentials are recorded here.

The news model call fails first. The pipeline then raises `News synthesis returned no report`, the analysis service returns HTTP 502, and the scheduler stores `The analysis failed. No strategy was activated.` These later messages hide the provider's original reason in the run overview. Strategy analysis does not proceed past the failed news stage.

On 5 October, both 00:30 midnight reviews failed. The 05:30, 12:30, 15:30, and 19:00 reviews for each asset were still scheduled at inspection. On 4 October, both assets' 05:30, 12:30, 15:30, and 19:00 reviews failed with the same provider error. The 4 October 00:30 reviews were cancelled because no trade slots were available.

The OpenRouter key allowance must be restored or the key replaced before model calls can succeed. Debug logging does not remove this limit.

- The analysis, trading, BTC market-data, and ETH market-data containers were healthy, with zero restarts and no OOM kills.
- Host disk usage was 30%, memory availability about 8.5 GiB, and swap usage zero.
- The trading scheduler was running with no last error, no database waiters, two connected private streams, and a connected change feed. No analysis jobs were running or stuck.
- Both market-data services had no warning or error logs since midnight.
- Nineteen older strategies had `attention` status with `Entry not placed: Account capital is already reserved`. The newest was created on 2 October. These are separate from the model failures.
- Trading logs recorded temporary DNS failures and private-stream disconnections around 01:36 IST. This was after the 00:30 model failures. Private streams were connected at inspection.

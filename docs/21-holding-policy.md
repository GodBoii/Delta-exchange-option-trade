# Exit choices and contract expiry

Saved strategy templates contain legs, strike selection, order settings and risk controls. They do not contain an entry time, exit time or contract expiry. Each new scheduled run owns its resolved schedule and expiry. Older run snapshots keep their original definitions.

Both the agent and manual schedule preview use the server's exit resolver. New choices are an intraday preset of seven hours or a specific timezone-aware exit timestamp within that maximum. Only the stored `new_york_session` agent review can use eleven hours. Manual schedules, follow-ups, midnight, Asia, London and pre-expiry reviews have a seven-hour maximum. Overnight, positional and first/second listed-expiry choices are no longer accepted.

The only eligible contract expiry is the upcoming 17:30 IST session boundary. After that boundary, this means the following calendar day's expiry. Every leg and strike rule must resolve at that expiry; missing contracts produce rejection rather than a later-expiry fallback. Intraday presets shorten automatically to the saved expiry safety cutoff, so London and pre-expiry trades can last less than seven hours. Explicit custom exits that exceed the session cutoff or maximum duration are rejected. Evening trades may cross midnight but never the upcoming expiry boundary. A review cannot defer entry into a different options session.

The preview returns entry and exit in UTC and IST, elapsed minutes, maximum holding hours, the chosen contract settlement, and the latest buffered exit. Selection requires the current saved version and market snapshot; the compact path requires the same successful preview arguments. The writer independently validates new agent proposals against its stored review trigger and time. A manual schedule carries the preview's exit and expiry; the server rejects it if either changed. At activation, the engine resolves the live chain and checks the selected products' actual settlement before any order is sent.

Stops and profit targets can close a strategy earlier than the scheduled exit. These choices do not extend or modify an active trade. The proposed future monitoring rules are recorded in [future active-trade monitoring](26-future-active-trade-monitoring.md).

Existing pending schedules, active trades and completed snapshots keep their original definitions. Their assigned-expiry rechecks and execution protection remain available. See [current-session inputs and scheduling](32-current-session-options.md) for the October 8 change and validation.

After building the matching writer and research images, run `python -m scripts.shared_library exit-templates` from `backend` to review the saved-library conversion. Run it again with `--apply` during the service handoff. The command refuses to convert while a future proposal awaits activation. It increments each changed template version once, leaves completed and open run snapshots alone, and retires the five duplicate next-day templates. Rerunning it makes no further changes.

# Reliability and performance implementation

Agreed scope: Supabase retains login, authentication, user metadata and its profiles table. Ubuntu PostgreSQL owns application profile reads, owner roles, trading and research. Local profile changes mirror asynchronously to Supabase. Preserve owner capabilities, existing strategy rules, order identities, account isolation, capital accounting and public API compatibility. Do not refresh main-analysis market packets or change decision-report/citation behavior.

1. Trace existing profile, account/session, journal, scheduler, feed and frontend callers. Establish current regression results and identify disposable database verification.
2. Add an additive local profile schema, trusted initial import, local reads/search and a durable coalescing mirror queue. Bootstrap existing owner roles only from trusted Supabase rows. Never derive owner privileges from user-editable auth metadata. Local reads remain available during a Supabase outage; mirror failures cannot block trading. Provide authenticated local profile edits and owner-controlled role changes.
3. Persist retry attempts, deadlines and escalation independently of process lifetime. Distinguish known pre-submission rejection, transport failure, unknown dispatch, partial execution, expired products and account/transfer uncertainty. Never resubmit an unknown order or free uncertain exposure. Exhausted automated reconciliation remains visible and explicitly resumable; live-position monitoring remains active.
4. Run risk evaluation independently of due entry/exit batches. Preserve strategy operation guards and account coordination. Expose progress, overdue monitoring and recovery escalation in private operational health.
5. Reuse leased exchange clients in recurring HTTP handlers. Replace credential I/O under the global session lock with per-user coordination that also serializes invalidation. Clean idle sessions periodically, preserve shared wallet rate histories, and bound reloadable product/wallet metadata.
6. Replace whole-book sorting with top-K selection, maintain incremental CVD with wall-clock expiration, and serialize each published market snapshot once. Preserve depth sequence guarantees, the existing stream message shape, bounded slow-client queues and agent packet timing.
7. Project requested fields in PostgreSQL and preserve report hydration/projection semantics. Add backward-compatible strategy pagination and complete attention counts. Read all working-order pages. Connect revision streams to authentication changes and prevent stale responses from overwriting newer state.
8. Remove only proven unused helpers/dependencies. Retain operational scripts and tested public helpers whose removal adds compatibility risk. Exclude environments from ESLint and include news-agent tests in standard pytest discovery.
9. Run targeted and complete tests, including real disposable PostgreSQL migrations and data-access tests. Verify concurrent accounts, outages/restarts, retry exhaustion, owner preservation, profile mirror recovery and market/stream equivalence. Run TypeScript, lint, frontend tests and browser checks. Record limitations and rollout instructions.

Work on main only. Commit each changed file separately, push tested batches to origin main, and keep secrets/unrelated files out. Production deployment and historical recovery changes require their own verified rollout; developing and testing these changes must not place orders or modify live balances.

Acceptance requires backward-compatible migrations, durable profile synchronization, bounded automated recovery without lost exposure, continued risk evaluation during slow execution, complete list navigation and unchanged excluded agent/report behavior.

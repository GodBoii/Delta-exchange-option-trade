# Trade Cognition local storage cutover

> Superseded: Convex and the recovery mirror are retired. See [Local storage](25-local-only-storage.md).

This runbook applies only to Trade Cognition. Supabase Auth, Agno sessions, analysis reports and chart storage stay where they are. PostgreSQL on Ubuntu becomes authoritative. Convex keeps a delayed, private recovery copy and sanitized read-only views. The cutover requires the existing trading writer to be paused with no open exchange exposure.

## Current stop conditions

The September Convex team I/O allowance was already exceeded when this implementation was prepared. A live read on September 25 found two active strategies and four product claims. Do not run the export, recovery seed or storage switch while either condition remains. Database I/O is shared with the separate polycognition project. Inspect the team usage page again after the monthly reset, and confirm that an export plus seed fits the remaining allowance.

The final gate must show zero scheduled, active, executing and attention strategies, zero product claims, zero unresolved order intents, and zero running analysis jobs. Also check Delta positions and executable orders through the existing authenticated account APIs. A Convex count alone cannot prove flat exchange exposure. Never cancel or close a funded position merely to make the migration gate pass.

5. Deploy the additive `convex/recovery.ts` functions and schema to the **Trade Cognition** deployment after the usage allowance resets. Keep `CONVEX_LIBRARY_WRITES_PAUSED` unset until the final pause. Do not deploy to polycognition.

## Final transfer

1. Recheck the stop conditions and quota. Stop the trading writer and research service. Keep the old frontend from accepting new library edits by setting `CONVEX_LIBRARY_WRITES_PAUSED=true` on Trade Cognition after deploying the guard. Confirm one browser save attempt is rejected. If the condition cannot be established, restart the old writer and stop here.
2. From the authenticated local checkout, export only the Trade Cognition deployment with `npx convex export --deployment knowing-horse-0 --path <private local path>`. Transfer the ZIP over SSH into a restricted Ubuntu cutover directory. Keep it out of Git and public storage. Re-run the count and flat-exposure checks; if anything changed during the pause, do not import that snapshot as final.
3. Initialize an empty local database, create the reader role, and run `python -m scripts.import_convex_export <source.zip> --apply --source-paused` in a one-off backend container with the ZIP mounted privately. The importer verifies every supported table and queues an initial Convex recovery event for each record. A mismatch rolls back the transaction. Decrypt and verify every connected account with the existing `CONVEX_CREDENTIAL_KEY`; retain that key separately from the database volume.
4. Set `APPLICATION_STORAGE=local` in Ubuntu `backend/.env`. Keep `RECOVERY_MIRROR_ENABLED=false` until the replacement Convex account is configured; `/health` reports this explicitly. Start with `SCHEDULER_ENABLED=false` and `AUTOMATION_SCHEDULER_ENABLED=false`, verify local reads and Delta reconciliation, then enable the schedulers. The outbox accumulates durable events locally while the mirror is disabled. When the replacement Convex deployment is ready, configure its URL and service secret, seed its recovery tables from the verified local state, set `RECOVERY_MIRROR_ENABLED=true`, and restart. Poll `/health` until `recoveryMirror.pending=0`, `lagAlert=false`, and `lastError=null`; verify its manifest and owner-scoped read-only queries.
5. Build the Vercel frontend with `NEXT_PUBLIC_APPLICATION_STORAGE=local` and the same `NEXT_PUBLIC_CONVEX_URL`. Verify authenticated library reads, a version-checked save, an automation context read, both account views and the offline read-only view. Reconcile the local state with Delta once more. Enable the two schedulers and restart exactly one Ubuntu trading writer and the research service. Keep the old Convex tables read-only and the browser-write freeze enabled.

## Operation and recovery

The local PostgreSQL transaction commits before an exchange order is sent. The mirror normally sends pending outbox events within five seconds but never gates an order. `/health` reports its oldest pending event, lag and last error. Alert on lag over one minute. Risk display updates stay local; order intents, outcomes, fills, capital claims and meaningful state changes enter the recovery outbox. Daily manifests record counts, revision checksum and the last delivered outbox ID. Completed recovery records are retained for 90 days; full history remains local.

If the Ubuntu service restarts with its disk intact, PostgreSQL replays WAL. The backend retries the outbox and reconciles unresolved order identities against Delta before normal scheduling. If the disk is lost, create a new empty PostgreSQL database, export Convex recovery data, and run `python -m scripts.restore_local_from_recovery <export.zip> --apply --source-confirmed`. This leaves `trade.recovery_gate.pending=true`. The backend then serves reads and rejects writes. Review manifest differences, decrypt credentials with the separately retained key, and reconcile every open position, executable order, claim and uncertain intent against Delta. Only then run `python -m scripts.clear_recovery_gate --manifest-reviewed --delta-reconciled` and restart the writer. An asynchronous mirror can miss the last few seconds before total disk loss; the restored copy alone never authorizes another order.

Do not point an old backend at retained Supabase trading tables. They were removed in the September cutover. Rollback after local writes requires a stopped writer and a reviewed reverse transfer. The separate polycognition project is outside this runbook.
